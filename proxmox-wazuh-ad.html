Project Summary

Built, recovered, and validated a multi-VM cybersecurity lab on Proxmox VE behind a pfSense-segmented network. The project progressed from virtualization and network recovery into centralized Wazuh monitoring, Active Directory security-event validation, File Integrity Monitoring, SOC-style event correlation, privileged Domain Admins membership monitoring, custom Wazuh detection engineering, and email alert delivery.

October 1 — Proxmox Build and VM Foundation

  • Deployed Proxmox VE on dedicated hardware and integrated it with the isolated 192.168.10.0/24 cybersecurity lab network.
  • Configured the Proxmox management address as 192.168.10.80/24 with pfSense gateway 192.168.10.1.
  • Created and configured Ubuntu Server, Kali Linux, Wazuh Server, and Windows Server 2022 virtual machines.
  • Established the base architecture for Windows, Linux, SIEM, and Active Directory testing.

October 2–3 — Network Recovery and Wazuh Integration

  • Diagnosed a Proxmox connectivity failure where the host at 192.168.10.80 became unreachable from the Windows management system.
  • Verified the Proxmox route table still contained the default route through 192.168.10.1 on vmbr0.
  • Reviewed /etc/network/interfaces and confirmed the static bridge configuration for vmbr0.
  • Used bridge link show, ip addr, and interface-state checks to isolate the problem to the physical NIC / live bridge path.
  • Brought the physical interface back up, restored bridge connectivity, and repeatedly re-tested the gateway and Windows management endpoint.
  • Confirmed successful Windows-to-Proxmox ICMP testing with 0% packet loss after recovery.
  • Restored access to the Proxmox web interface at https://192.168.10.80:8006.
  • Reviewed pfSense lab addressing and static mappings during validation.
  • Verified Wazuh Manager, Indexer, and Dashboard services and enrolled Windows, Windows Server, Ubuntu, and Kali endpoints.
  • Confirmed Windows security-event collection, including failed-logon alerting from Windows Server 2022.

October 5 — Custom Wazuh Level 14 Detection and Email Alerting

Extended the privileged-group monitoring workflow by creating a custom Wazuh child rule for Domain Admins membership changes. The custom detection was linked to built-in Wazuh rule 60159, assigned Rule ID 100100, and raised to Level 14.

  • Matched the Domain Admins target group using a PCRE2 field condition.
  • Validated the custom rule with controlled Event IDs 4728 and 4729.
  • Confirmed Wazuh displayed rule.id: 100100, rule.level: 14, and the description CRITICAL: Privileged Domain Admins membership changed.
  • Configured Postfix on the Wazuh server as a local SMTP relay.
  • Configured authenticated Gmail relay using TLS, SASL, Google 2-Step Verification, and a dedicated App Password.
  • Used mailq to diagnose an initial Gmail authentication failure and corrected the credential method.
  • Verified a standalone Postfix test email before enabling Wazuh notifications.
  • Triggered another controlled privileged-group change and received a Wazuh email containing Alert level 14, Rule 100100, Event ID 4728, and the Domain Admins context.

End-to-end workflow: Active Directory change → Windows Security Event → Wazuh detection → custom Level 14 rule → Postfix relay → Gmail alert.
